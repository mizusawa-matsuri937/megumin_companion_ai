# Megumin Desktop Companion AI：Codex 协作开发计划

> 计划口径：单人开发、Codex 辅助、每天约 4～6 小时有效开发时间。计划按 **31 个有效开发日** 估算；新增的本地 STT 专项日使用了原 30 日目标的 1 天缓冲，整体仍允许在原目标上 `±5` 天浮动，不等同于连续自然日。
>
> MVP 目标：在 Windows 上得到一个可日常试用的桌面陪伴原型——用户既可以通过本地按键说话和本地 STT 进行语音交流，也可以打开桌面对话框打字交流；系统能连接 VTube Studio、流式回复、本地 TTS 说话、响应打断，在总开关授权后保存 AI 判定的重要对话记忆，在视觉开关授权后低频且隐私优先地观察当前活动窗口，并低打扰地主动发话，同时提供必要的托盘控制和可运行安装包。

---

## 1. 计划原则

### 1.1 Codex 能节省什么时间

Codex 优先承担以下工作：

- 工程脚手架、重复代码和配置模板。
- Mock、测试夹具、单元测试和大部分集成测试初稿。
- Provider/API 适配代码、数据模型、纯函数和常规错误处理。
- 日志、指标、调试接口、文档同步和机械性重构。
- 根据失败日志定位问题、提出修复方案并执行经过授权的代码修改。

这些工作通常能明显减少查资料、写样板代码和补测试的时间，因此计划从原来的 35 天压缩为 31 个有效开发日，同时把更多时间留给真实环境验收。

### 1.2 Codex 不能替代什么

以下结果必须由开发者亲自判断，不能以“测试通过”或 Codex 的自我检查代替：

- VTube Studio 的授权弹窗、模型动作、表情和断线恢复是否真实可用。
- GPT-SoVITS 的安装、显存/内存占用、实际音质、首句延迟和授权素材边界。
- 用户是否感觉回复自然、表情恰当、语音不突兀、主动发话不打扰。
- 屏幕截图、OCR、日志、缓存和网络请求是否可能泄露敏感信息。
- 记忆是否准确、可解释、可查看、可删除，并且删除后确实不再被使用。
- Windows 多显示器、DPI、音频设备、托盘、打包、杀毒软件和开机启动行为。
- API key、声音、Live2D 模型、图片和其他受版权或隐私保护资源是否合规。

### 1.3 三种协作标记

| 标记 | 含义 | 工作方式 |
| --- | --- | --- |
| **AI 主导** | 规则明确、容易自动测试 | Codex 实现和测试，人工阅读关键 diff 并运行验收命令。 |
| **人机协作** | 同时包含代码和真实环境行为 | Codex 编写代码与测试，人工操作外部软件、提供观察结果并决定是否通过。 |
| **人工关卡** | 涉及隐私、安全、体验、硬件或发布 | Codex 可以辅助检查，但只有人工验收并记录结果后才能进入下一阶段。 |

> 所有 Codex 生成的代码都需要进入正常代码审阅和测试流程；“AI 主导”不代表无需人工负责。

## 2. MVP 范围调整

### 2.1 本计划必须完成

- 单进程模块化 Python App，VTube Studio 和 GPT-SoVITS 作为外部进程。
- FastAPI `/health`、最小 WebSocket/输入入口和生命周期管理；文字与语音输入统一转换为同一种 `UserMessage`，复用同一条对话流水线。
- 本地按键说话、本地 STT、原始录音即时清理和键盘输入降级；不持续监听，不使用云端 STT。
- 最小桌面对话框：消息列表、文字输入框、发送按钮/快捷键、流式回复显示、打断按钮和连接状态；桌面客户端不得直接请求云端 LLM。
- Mock 与真实 OpenAI-compatible LLM 流式输出。
- Segmenter、TTS 队列、有序播放、取消、超时和降级。
- VTS 连接、认证 token、基础表情热键、重连和无 VTS 降级。
- 最小情绪状态及其对 Prompt、TTS、VTS 的映射。
- SQLite 最近 7 天对话、用户画像，以及记忆总开关授权后的自动重要记忆；提供查看、修改、删除和禁用能力。
- 默认关闭的视觉总开关、活动窗口、Privacy Guard、受控截图、变化检测、OCR、基础场景分类和可选云端视觉分析。
- 默认关闭的主动发话总开关，以及评分、冷却和抑制。
- 托盘核心开关、桌面对话框、调试状态、Windows 打包和回归测试。

### 2.2 移出 MVP

以下内容进入 MVP 后续版本，不占用本计划工期：

- 通用插件系统、插件沙箱、AstrBot、游戏和日程插件。
- 插件市场或复杂权限管理 UI。
- ChromaDB/FAISS 默认接入；基础 SQLite 检索不够用时再做独立技术验证。
- 自动从屏幕推断并写入长期记忆。
- 复杂每日 Diary、复杂记忆合并和大规模 RAG。
- 精美设置页、复杂对话框皮肤/消息动画、复杂字幕动画和自研 Live2D 渲染器；最小文字对话框仍属于 MVP。
- 自动控制电脑、深度 QQ/微信集成、本地大语言模型和模型训练。
- 持续监听、唤醒词和云端 STT。

### Phase 2：真实 VTS、LLM、TTS 主链路（Day 8～14）

| 天数 | 协作方式 | 当天目标 | Codex 主要工作 | 必须人工审阅/验收 | 当天完成标准 |
| ---: | --- | --- | --- | --- | --- |
| Day 8 | 人机协作 | VTS APIState、token 申请、安全保存和复用。 | 实现 WebSocket 协议、认证流程、token store、超时和错误分类。 | **人工在 VTS 中点击 Allow，检查 token 只保存在本地忽略目录且日志不输出 token。** | 首次可授权，第二次可复用；VTS 未启动时主程序不崩溃。 |
| Day 9 | 人工关卡 | VTS 基础表情、热键映射、重连和降级。 | 实现 neutral/happy/shy/proud 热键、缺失热键提示、断线重连和状态事件。 | **人工观察真实模型逐个触发表情，手动关闭/重启 VTS 验证恢复行为。** | 表情与日志一致；断线期间文字/语音链路仍工作；重连后可继续触发。 |
| Day 10 | 人机协作 | 接入一个真实 OpenAI-compatible LLM Provider。 | 实现 streaming、超时、取消和限流/网络错误映射；Mock 仅用于开发测试，生产失败不自动回退到 Mock 或本地 LLM。 | **人工检查 API key 使用方式、请求目标、费用和失败提示；使用低额度测试密钥完成真实对话。** | 真实 token 流进入同一 Segmenter；断网或失败时给出可解释错误并结束当前 turn，不会拖死或伪造回复。 |
| Day 11 | 人工关卡 | GPT-SoVITS 环境、健康检查和最小 `/tts` 调用。 | 编写健康检查、请求模型、响应格式探测和最小音频保存/播放工具。 | **人工安装和启动服务，确认模型/参考音频具有合法授权，并实际听取输出。** | 输入一句测试文本可得到并播放有效音频；失败信息能够定位环境或参数问题。 |
| Day 12 | 人机协作 | TTS preset、格式统一、缓存、超时和字幕降级。 | 实现情绪 preset 占位、缓存 key、音频格式校验、单句超时与纯字幕降级。 | **人工比较音质、语速、冷启动和缓存命中体验；确认缓存不包含不应长期保存的敏感文本。** | TTS 单句失败不阻塞整轮；相同合法请求可复用缓存；临时文件可清理。 |
| Day 13 | 人工关卡 | 联通真实 LLM → Segmenter → TTS → Audio → VTS，并进行压力测试。 | 编写完整集成测试、故障注入、队列状态和延迟报告。 | **人工进行长回复、快速打断、连续提问、断网、关闭 TTS/VTS 等测试，判断首句等待是否可接受。** | Gate B 主链路通过：能说、能动、能被打断；所有外部服务都有可解释降级。 |
| Day 14 | 人工关卡 | 第一次 Windows 打包冒烟和架构复盘。 | 生成最小打包配置、检查资源路径，依据真实调用链删除空抽象并更新文档。 | **人工在 Windows 上启动打包产物，检查音频、端口、防火墙、路径和进程退出；决定是否需要调整模块边界。** | 打包版本能启动主链路；关键问题已记录并分级；不把打包风险拖到最后一天。 |

## 4. 阶段关卡

| 关卡 | 最低验收结果 | 一定要人工验收的原因 |
| --- | --- | --- |
| Gate A：Mock 主链路 | 流式输出、分句、Mock TTS、有序播放、取消和指标全部可重复测试。 | 快速输入和播放设备行为无法只靠单元测试判断。 |
| Gate B：真实主链路 | 真实 LLM、GPT-SoVITS、VTS 联通；能说、能动、能被打断；故障可降级。 | 涉及外部软件授权、声音、模型动作、设备和真实延迟。 |
| Gate C：情绪人格 | 情绪影响回复、语音和表情，但不过度、不闪烁、不越界。 | 自然度、角色边界和体验属于主观产品判断。 |
| Gate D：记忆 | 自动重要记忆可见、可解释、可改、可删、可禁用；敏感个人事实二次确认；不保存凭据、屏幕内容或 AI 推测。 | 涉及用户信任、隐私和持久化数据真实性。 |
| Gate E：屏幕隐私 | 视觉默认关闭；敏感场景不截图、不 OCR、不上传；Guard 错误跳过；合规窗口的截图出口与临时生命周期可核验。 | 这是项目最高风险数据流，必须由人检查实际系统和文件。 |

| Gate G：发布候选 | 干净 Windows 可运行；本地按键说话/STT 和文字对话框均能完成对话、流式显示与打断；核心回归通过，无敏感/侵权资产，无阻塞问题。 | 麦克风、输入法、桌面 UI、发布责任、许可、系统兼容和最终风险必须由开发者承担。 |

未通过关卡时，不进入依赖该能力的下一阶段。允许 Codex定位和修复问题，但修复后必须重新执行对应人工验收。

## 5. 每日完成定义（Definition of Done）

当天任务只有同时满足以下条件才算完成：

1. 验收标准可以通过命令、日志或人工操作重复证明。
2. 新增行为有与风险相称的单元测试或集成测试。
3. Codex 已说明修改范围、关键假设和未验证部分。
4. 人工阅读关键 diff；并发、取消、数据库、隐私、密钥、网络和文件删除逻辑必须重点审阅。
5. 相关文档和配置示例同步更新。
6. 仓库中没有 API key、真实聊天、真实截图、真实记忆、声音样本、Live2D 模型或其他未授权资源。
7. 若涉及人工关卡，验收结果和发现的问题已记录；不能用“Codex 认为完成”替代。
8. 对话框未发送的文字草稿不会进入网络请求、日志、数据库、记忆或调试状态。

## 6. 工期和缓冲规则

- 31 天任务表包含真实本地 STT 使用的 1 天原计划缓冲；相对原 30 天目标仍允许 ±5 个有效开发日浮动。
- Codex 主要缩短编码、测试初稿、查错和文档时间，不会显著缩短模型安装、真实设备测试、隐私审计和体验观察时间。
- 任一任务连续两天未通过验收，应缩小范围或增加诊断日，不把未解决问题带入后续阶段。
- Gate B、D、E、G 各自允许额外增加 1～2 天，不应通过降低人工验收标准追回进度。
- 每次只实现当前纵向闭环所需接口；没有第二个真实实现时，不提前建设复杂抽象。
- 如果基础 SQLite 检索已经满足 MVP，不因为原架构提到向量库而强行加入 ChromaDB/FAISS。
- 插件系统、复杂 Diary、精美 UI 和其他后续功能统一进入 MVP 之后的 backlog。

一句话执行原则：**让 Codex 加速可自动验证的工程工作，让人工牢牢掌握隐私、安全、版权、真实设备、角色体验和最终发布决定。**
