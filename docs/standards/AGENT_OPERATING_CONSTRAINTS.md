# Agent 工作规范与证据口径

> 强制规则的简明版本位于根目录 [`AGENTS.md`](../../AGENTS.md)。本文件解释执行方式；冲突时以用户最新指令、
> `AGENTS.md` 和已验证事实为准。

## 1. 证据与陈述

使用下列状态词，避免将计划、推测和实现混为一谈：

| 状态 | 含义 | 最低要求 |
| --- | --- | --- |
| 已确认 | 当前代码、命令、GitHub/平台查询或人工批准可直接证明 | 给出可复核路径、提交、命令或链接 |
| 合理推测/建议 | 基于现有证据的判断，不等于事实 | 写明前提和风险 |
| 未验证 | 现有环境无法直接证明 | 说明缺口和最小验证方式 |
| 已完成/已合并 | 交付状态而非开发意图 | 绑定 exact commit/PR/Gate 与验证结论 |

历史报告中的测试数量、PR 状态、日期和完成判断会过期。执行或报告前应在目标提交和当前远端状态上重新核验。

## 2. 文档作为系统的一部分

- `docs/current/` 只放共享的当前产品目标和阻塞，不记录会话噪声或秘密。
- `.agents/CONTEXT_MEMORY.md` 是本地、短期、可恢复的会话状态。它不取代 `docs/current/`，也不得泄露进 Git。
- 修改架构、风险、范围或验收时，先找出受影响的计划、ADR、决策、威胁模型、数据流、实现记录和 Gate；
  同步更新或明确记录为何不受影响。
- 不批量移动已有文档以追求目录整齐，除非迁移本身有范围、链接清单、验证和独立提交。稳定路径优先于表面整洁。
- 每个新增文档都要在 [`../README.md`](../README.md) 登记；失效文档需保留其历史定位并指向当前权威来源。

## 3. AI 优先审计的执行顺序

对审计、review、验收或发布门，按下列顺序尽可能自动完成：

1. 精确 diff、代码路径和配置审查；
2. 静态分析、格式、类型、依赖/许可证/漏洞与 secret/path 扫描；
3. 聚焦测试、完整测试、property/stress/fault-injection 和隔离产物检查；
4. 可机器读取的 GUI、无障碍、几何、截图、运行时和网络边界证据；
5. 明确记录仍不可自动化的断言，并只把这些交给人工。

人工 Gate 必须写清：为何 AI 无法可靠验证、AI 已覆盖哪些条件、最小可复现步骤和明确的 pass/fail 标准。
不得让人工重复机器已证明的断言，也不得把模拟结果表述成真实硬件/OS/IME 证据。

## 4. 数据、资产和范围保护

- 默认将个人对话、截图、录音、声纹/声音、token、secret、路径、数据库和日志视为不可提交数据。
- 受保护角色相关模型、纹理、图像、语音、动作和用户导入资产不得入库；需要测试时使用已授权的合成占位物。
- 真实 provider、隐私能力、网络/IPC、Windows ACL/DPAPI、安装器和设备行为必须按其特定契约与真实边界审计；
  loopback、Mock 或单元测试绿灯不自动消除风险。

## 5. 提交、发布和审计闭环

- 保留用户已有的无关改动；提交前只暂存本任务的预期路径并查看 staged diff。
- Wxx 任务必须遵循 `AGENTS.md` 的 Draft PR、exact-head 检查和 guarded merge 规则。
- 文档任务同样需要检查链接、术语、状态声明和 `git diff`；若用户授权推送，提交信息应说明文档治理/状态范围。
- 发现证据与文档冲突时，先标为冲突并停止夸大结论；根据当前代码和可复现证据修正权威状态，再继续。
